    V = Value (what information does that thing have?)
    
    Example: Processing sentence "The cat sat on the mat"
    - When processing "mat", query asks "which words relate to 'mat'?"
    - Keys tell us what each word represents
    - Values give us actual content of related words
    
    Result = Weighted combination of values based on attention scores! 📊
    """
    
    # Step 1: Compute attention logits (raw scores)
    logit_matrix = np.dot(Q, K.T) / sqrt(d_model)  # Shape: [batch, seq_len, seq_len]
    
    # Example with 3 tokens in sequence:
    """
       Query[0]=The   Q[1]=cat   Q[2]=sat
      ┌──────────────┬─────────────┬─────────────┐
      │ K·Q.T / sqrt(│         │          │           │
      │ d_model)     │    Score    │  Attention  │    Output = Σ(attn*value)
      ├──────────────┼─────────────┼─────────────┤
      │ The attends   │ to: [0.9,  │ to:          │ 
      │ to positions  │  0.1, 0.0]  │ weighted sum │
      │ with weights  ├─────────────┼─────────────┤
      │               │ cat[0.1]   │ of values!   │
      └──────────────┴─────────────┴─────────────┘"""
    
    # Step 2: Apply softmax to normalize scores into probabilities
    attn_weights = torch.softmax(logit_matrix, dim=-1)
    # Each row now sums to 1.0 (probability distribution over positions)
    
    # Step 3: Weighted sum of values
    output = torch.matmul(attn_weights, V)  # [batch, seq_len, d_model]
    
    return output

"""Why divide by sqrt(d_model)?
Without scaling, attention scores grow with dimension size.
For high-dimensional vectors (512+), softmax becomes too peaked!
Scaling keeps gradients flowing properly during training."""```

### Multi-Head Attention: Parallel Perspectives 🔄

Instead of one monolithic attention mechanism, we split into multiple "heads":

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        
        self.num_heads = num_heads  # Split into 8 parallel attentions
        assert d_model % num_heads == 0
        
        dim_per_head = d_model // num_heads  # Each head gets 64 dimensions
        
        # Create separate linear projections for each head
        self.q_proj = nn.Linear(d_model, d_model)   # Queries
        self.k_proj = nn.Linear(d_model, d_model)   # Keys  
        self.v_proj = nn.Linear(d_model, d_model)   # Values
    
    def forward(self, x):
        """Process all 8 heads in parallel"""
        
        Q = self.q_proj(x)      # [batch, seq_len, d_model]
        K = self.k_proj(x)      
        V = self.v_proj(x)
        
        # Split each into num_heads separate matrices
        # Q: [batch, seq_len, 8*64] → reshape to 
        #    [batch, num_heads=8, seq_len, dim_per_head=64]
        new_q_shape = (Q.size(0), self.num_heads, -1) + Q.shape[2:]
        
        return torch.cat([head(Q, K, V) for head in range(self.num_heads)], 
                         dim=-1)

"""Visualizing Multi-Head Attention:

Original sequence of 8 dimensions gets split into 4 "perspectives":

Head 0 (Semantic):   [the] → attends strongly to [cat], [dog]
Head 1 (Syntactic):    [the] → looks for determiner relationships  
Head 2 (Positional):  Focuses on word order patterns
Head 3 (Topic):      Identifies subject-object dependencies

Each head learns different "what" and "how" to attend! 🧩"""```

### Different Types of Attention Applications

| Application | How It Works | Example Use Case |
|------------|--------------|------------------|
| **Self-Attention** | Token attends to other tokens in same sequence | Language understanding within a sentence |
| **Cross-Attention** | Decoder queries encoder outputs | Translation (source language → target language) |
| **Sparse Attention** | Only attends to specific positions | Long sequences, reducing computation |
| **Linear Attention** | Uses kernel tricks for efficiency | Very long documents (>10k tokens) |

### Building a Simple Transformer from Scratch (PyTorch Style)

```python
import torch
import torch.nn as nn
import math

class ScaledDotProductAttention(nn.Module):
    """Single attention head"""
    
    def __init__(self, d_model):
        super().__init__()
        self.d_k = d_model // 8
    
    def forward(self, Q, K, V, mask=None):
        scores = torch.matmul(Q / math.sqrt(d_model), K.transpose(-2, -1))
        
        if mask is not None:
            scores.masked_fill_(mask == 0, -1e9)
        
        weights = torch.softmax(scores, dim=-1)
        output = torch.matmul(weights, V)
        return output

class MultiHeadAttention(nn.Module):
    """Full multi-head attention module"""
    
    def __init__(self, d_model, num_heads=8):
        super().__init__()
        self.num_heads = num_heads
        assert d_model % num_heads == 0
        
        dim_per_head = d_model // num_heads
        
        # Linear projections for each head type (Q, K, V)
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model) 
        self.v_proj = nn.Linear(d_model, d_model)
        
        # Output projection to recombine heads
        self.o_proj = nn.Linear(d_model, d_model)
    
    def forward(self, Q_in, K_in=None, V_in=None):
        """If no separate keys/values provided, use same input"""
        if K_in is None:
            K_in = Q_in  # Self-attention case
            
        if V_in is None:
            V_in = Q_in
        
        # Project inputs to query/key/value spaces and reshape for heads
        q_proj_out = self.q_proj(Q_in).view(
            *Q_in.shape[:2], 
            self.num_heads, -1)  # [batch, seq_len, num_heads, dim_per_head]
        
        k_proj_out = self.k_proj(K_in).view(*K_in.shape[:2], self.num_heads, -1)  
        v_proj_out = self.v_proj(V_in).view(*V_in.shape[:2], self.num_heads, -1)
        
        # Compute attention scores and weighted values for each head separately
        attn_output_per_head = scaled_dot_product_attention(q_proj_out, k_proj_out, v_proj_out)
        
        # Concatenate all heads back together
        output = torch.cat(attn_output_per_head, dim=-2).transpose(-1, -2)  # [batch, seq_len, d_model]
        
        return self.o_proj(output)

class TransformerEncoderLayer(nn.Module):
    """Single encoder layer with attention + feed forward"""
    
    def __init__(self, d_model=512, num_heads=8, dim_ffn=2048):
        super().__init__()
        
        # Attention sublayer (with normalization)
        self.attention = MultiHeadAttention(d_model=d_model, num_heads=num_heads)
        self.norm1 = nn.LayerNorm(d_model)  # Normalize before attention
        
        # Feed forward network (expand then compress dimensions)
        dim_ffn_expanded = d_model * 4     # Common practice: expand by factor of 4
        self.feed_forward = nn.Sequential(
            nn.Linear(d_model, dim_ffn),    # Expand dimensionality
            nn.GELU(),                      # Non-linear activation (Gaussian Error Linear Unit)
            nn.Linear(dim_ffn, d_model))   # Project back to original size
        
        self.norm2 = nn.LayerNorm(d_model)  # Normalize before feed forward
    
    def forward(self, x):
        """Process through attention then feed-forward with residual connections"""
        
        # Attention sublayer: normalize input → apply attention → add residual (input + output)
        attn_output = self.attention(x)
        x_after_attention = self.norm1(x + attn_output)  # Residual connection!
        
        # Feed forward network: same pattern with different transformation
        ff_out = self.feed_forward(x_after_attention)
        return self.norm2(x_after_attention + ff_out)

class TransformerEncoder(nn.Module):
    """Stack of encoder layers"""
    
    def __init__(self, num_layers=6, d_model=512, dim_ffn=2048, num_heads=8):
        super().__init__()
        
        # Stack identical transformer blocks (same architecture repeated)
        self.layers = nn.ModuleList([
            TransformerEncoderLayer(
                d_model=d_model, 
                num_heads=num_heads, 
                dim_ffn=dim_ffn
            ) for _ in range(num_layers)])  # Create N copies
    
    def forward(self, x):
        """Pass through all layers sequentially"""
        
        output = x  # Start with input embeddings
        
        for layer_idx, encoder_layer in enumerate(self.layers):
            output = encoder_layer(output)
        
        return output

# Example usage: Process a sentence through transformer
transformer_model = TransformerEncoder(num_layers=6, d_model=512, dim_ffn=2048)
sentence_embeddings = torch.randn(1, 30, 512)  # Batch of 1 sequence with 30 tokens

encoded_outputs = transformer_model(sentence_embeddings)
print(f"Output shape: {encoded_outputs.shape}")  # [batch_size, seq_len=30, d_model=512]
"""
Result: Each position now has context from ALL other positions in the sentence!
The model can understand relationships between distant words simultaneously. 🎯
"""```

### Model Architecture Variations

#### Encoder-Only Models (BERT family):

```python
"""Used for: Classification, Question Answering, Named Entity Recognition

Architecture: Only encoder layers, no decoder.
Training objective: Predict masked tokens from surrounding context.

Example tasks:
- Sentiment analysis ("This movie is amazing!" → positive)
- Spam detection
- Document classification (sports news vs politics)"""```

#### Decoder-Only Models (GPT family):

```python
"""Used for: Text generation, chatbots, code completion

Architecture: Only decoder layers with causal masking.
Training objective: Predict next token given all previous tokens.

Example tasks:
- Creative writing ("Once upon a time...")
- Chatbot responses  
- Code autocompletion (GitHub Copilot)"""```

#### Encoder-Decoder Models (T5, BART):

```python
"""Used for: Translation, summarization, text-to-image

Architecture: Full encoder-decoder with cross-attention.
Training objective: Transform input sequence to target output.

Example tasks:
- Machine translation ("The cat sat" → "El gato se sentó")  
- Text summarization (long article → 100-word summary)"""```

### Positional Encoding Variations 📍

Different ways to encode position information:

| Method | Pros | Cons | Use Cases |
|--------|------|------|-----------|
| **Sinusoidal** | Allows extrapolation, relative positions learnable | Fixed pattern learned from data | BERT original, GPT-2 |
| **Learned Absolute** | Simple to implement | Can't extrapolate beyond training length | Standard practice |
| **RoPE (Rotary)** | Relative position naturally encoded | More complex implementation | Modern large models |

```python
# RoPE Example - Positional encoding that's relative!
"""When processing tokens, each head stores a rotation matrix.
The dot product of Q and K includes the difference in rotations:

Q[i] · K[j]^T = f(Q)·f(K) · e^(iθ(i-j))  # Depends on position DIFFERENCE (i-j)!

This means attention naturally captures relative positions! 🎯"""```

## Training Best Practices 📚

### Pre-training vs Fine-tuning Pipeline

**Pre-Training Phase:**
1. Train on massive corpus (e.g., CommonCrawl - billions of words)
2. Use unsupervised objectives: predict masked tokens or next token
3. Model learns general language patterns and world knowledge

```python
"""BERT Pre-training Objectives:
A. Masked Language Modeling (MLM): 
   Input: "The cat sat on the [MASK] mat"
   Target: Predict "mat" from surrounding context
   
B. Next Sentence Prediction (NSP) for BERT-Large:
   Input pairs determine if sentence 2 follows sentence 1"""```

**Fine-tuning Phase:**
1. Load pre-trained weights
2. Add task-specific output layers (classification head, etc.)
3. Train on your specific dataset with labeled examples

### Hyperparameter Tuning Guide

| Parameter | Typical Range | Impact | When to Adjust |
|-----------|--------------|--------|----------------|
| **Learning Rate** | 1e-5 - 1e-4 (warmup) then decay | Speed of learning, stability | Start with standard schedule; reduce if loss spikes |
| **Batch Size** | 32 - 65536 (depends on GPU memory) | Training speed, generalization | Larger helps regularization but needs more VRAM |
| **Number of Layers** | 6-10 for encoder-only models | Model capacity/complexity | More layers = better performance but slower training |
| **Attention Heads** | 8-32 (depends on d_model) | Parallel processing capability | Usually power-of-2 values work well |

### Common Training Issues & Solutions

```python
"""Issue: Loss exploding during training
Symptoms: Training loss suddenly jumps to infinity, NaNs appear

Causes:
1. Learning rate too high → model overshoots minima
2. Gradient clipping not applied
3. Model instability in early layers

Solution:
- Reduce learning rate by 5x or implement gradient clipping (max norm = 1.0)"""```

### Evaluation Metrics Guide

| Task Type | Best Metric(s) | What It Measures |
|-----------|---------------|------------------|
| **Classification** | Accuracy, F1-score, AUC-ROC | Correct predictions vs actual labels |
| **Sequence-to-sequence** | BLEU score, ROUGE-L | Text similarity to reference translations/summaries |
| **Token prediction** | Perplexity (PPL), Cross-entropy loss | How well model predicts next token |

```python
"""Perplexity explained:
Lower is better! PPL = exp(average cross-entropy loss)

Example comparison for language models:
GPT-2-small:      PPL ≈ 18.0 (good baseline)  
My custom model:   PPL ≈ 35.0 (needs improvement)
"""```
